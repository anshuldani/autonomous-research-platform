# Architecture Documentation

## Overview

The Autonomous Research Platform uses a multi-agent architecture built with LangGraph to autonomously research topics using web search and AI synthesis.

## Core Components

### 1. State Management (`ResearchState`)
```python
class ResearchState(TypedDict):
    topic: str                          # User input
    research_questions: List[str]       # Generated by planning agent
    search_results: Dict[str, List]     # Web sources by question
    summary: str                        # Final synthesized report
    current_step: str                   # Progress tracking
```

**Purpose:** Shared data structure that flows through all agents.

**Pattern:** Immutable state updates - each agent returns modified copy.

### 2. Agent Pipeline

#### Planning Agent
- **Input:** User topic
- **Process:** Uses Claude to generate 3 focused research questions
- **Output:** List of specific, searchable questions
- **Technology:** Claude Sonnet 4 with JSON output

#### Research Agent  
- **Input:** Research questions
- **Process:** Searches web via Tavily for each question
- **Output:** Dictionary mapping questions to sources
- **Technology:** Tavily API with advanced search depth

#### Synthesis Agent
- **Input:** All search results
- **Process:** Claude synthesizes across sources
- **Output:** Comprehensive 400-500 word summary
- **Technology:** Claude Sonnet 4 with 2048 token limit

### 3. External Integrations

#### ResearchTools Class
```python
class ResearchTools:
    def __init__(self): ...
    def search_web(query, max_results=5): ...
    def _format_search_result(item): ...
```

**Responsibilities:**
- API client management
- Error handling
- Result formatting
- Future: More research tools

#### Tavily Integration
- Search depth: Advanced (full content extraction)
- Results per query: 3 (configurable)
- Response format: Clean JSON
- Content: Pre-extracted and formatted

### 4. Workflow Orchestration
```
StateGraph → add_nodes() → add_edges() → compile()
```

**Execution Flow:**
1. User provides topic
2. Graph invokes planning agent
3. State flows to research agent
4. State flows to synthesis agent
5. Final state returned to user

**Design Pattern:** Directed Acyclic Graph (DAG)

## Design Decisions

### Why LangGraph?
- **State Management:** Automatic state passing between agents
- **Visualization:** Built-in graph visualization tools
- **Debugging:** Easy to trace execution flow
- **Scalability:** Can add conditional edges, loops

### Why Separate Agents?
- **Modularity:** Each agent is independently testable
- **Clarity:** Clear separation of concerns
- **Flexibility:** Easy to swap implementations
- **Debugging:** Can test each agent in isolation

### Why Tavily over Google?
- **LLM-Optimized:** Returns clean, extracted content
- **Developer-Friendly:** Simple API, no complex auth
- **Cost-Effective:** Free tier sufficient for learning
- **Quality:** Advanced search with relevance scoring

## Error Handling Strategy

1. **API Failures:** Return empty lists, log errors
2. **Parsing Errors:** Handle JSON with/without markdown
3. **Empty Results:** Continue workflow, document in logs
4. **State Validation:** TypedDict provides runtime checks

## Testing Strategy

- **Unit Tests:** Mock external APIs, test logic
- **Integration Tests:** Test full workflow with mocks
- **Manual Tests:** `__main__` block for quick validation
- **Future:** Add property-based tests for robustness

## Day 3: RAG Architecture

### Vector Database Layer
```
┌─────────────────────────────────────────────────┐
│           Pinecone Serverless Index             │
│  - 1024-dimensional vectors (Voyage-3)          │
│  - Cosine similarity metric                     │
│  - Metadata filtering support                   │
└─────────────────────────────────────────────────┘
```

### RAG Pipeline
```
1. INGESTION:
   Web Content → Chunking → Embedding → Vector Storage
   
2. RETRIEVAL:
   Query → Embedding → Hybrid Search → Reranking → Top-K
   
3. GENERATION:
   Query + Retrieved Context → Claude → Synthesized Answer
```

### Embedding Strategy

**Model:** Voyage-3 (1024 dimensions)
- Optimized for retrieval tasks
- Better than OpenAI for RAG
- Input types: "document" vs "query"

**Why Voyage?**
- State-of-the-art retrieval performance
- Purpose-built for RAG
- Consistent 1024-d embeddings

### Chunking Algorithm
```python
chunk_size = 500 words
overlap = 50 words

Document → [Chunk 1] [Chunk 2] [Chunk 3]
              ↓          ↓          ↓
           Overlap   Overlap
```

**Why overlap?**
- Preserves context at boundaries
- Prevents information loss
- Improves retrieval quality

### Hybrid Search Formula
```
hybrid_score = (α × semantic_score) + ((1-α) × keyword_score)

where:
  α = 0.7 (default, configurable)
  semantic_score = cosine similarity
  keyword_score = term overlap / query_terms
```

### Reranking Architecture
```
Vector Search (top 20)
    ↓
Cohere Reranker (rerank-english-v3.0)
    ↓
Top 5 highest quality
```

**Why rerank?**
- Semantic search gets recall
- Reranker ensures precision
- Significantly better top-k quality

### Quality Metrics

Tracked per query:
- Retrieval method used
- Rerank scores distribution
- Chunk relevance scores
- Execution time

### Scalability Considerations

**Current limits:**
- Pinecone free tier: 100K vectors
- Voyage free tier: 200M tokens
- Query latency: <2s

**Production scaling:**
- Batch processing for bulk uploads
- Rate limit handling with exponential backoff
- Monitoring via index statistics

### Design Decisions

**Why Pinecone?**
- Serverless (no infrastructure)
- Production-ready
- Great free tier
- Easy metadata filtering

**Why not alternatives?**
- Weaviate: More complex setup
- Chroma: Not as scalable
- FAISS: Requires self-hosting

**Chunking size (500 words)?**
- Balances context vs precision
- Fits well in LLM context
- Empirically good for retrieval

**Alpha = 0.7?**
- Favors semantic (better for concepts)
- Still catches exact terms
- Tunable based on use case
